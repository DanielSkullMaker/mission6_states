1. ПОИСК ДАТАСЕТА
--------------------------------------------------------------------------------
Рассмотренные варианты:

  а) Kaggle "Brain Tumor MRI Dataset" (используется в Статьях 1/3) —
     ОТКЛОНЁН: отдельные анонимизированные снимки без привязки к пациенту/
     порядку срезов (это и было исходной причиной, по которой план требовал
     искать отдельный датасет для Статьи 4).

  б) Figshare "brain tumor dataset" (Cheng J., DOI 10.6084/m9.figshare.1512427,
     233 пациента, 3064 T1-снимка, те же 3 класса glioma/meningioma/
     pituitary, .mat-файлы с полями cjdata.PID/label/image) —
     ОТКЛОНЁН ДЛЯ СТАТЬИ 4, но ВАЖНАЯ НАХОДКА ДЛЯ СТАТЬИ 6: у каждого
     пациента вперемешку все 3 проекции (axial 994 / sagittal 1025 /
     coronal 1045 снимков по всему датасету) — группировка по PID не даёт
     физически смежных срезов одной оси, значит для сглаживания смежных
     векторов не подходит. НО: это именно та разметка по проекции
     (axial/sagittal/coronal), которой не хватает для Статьи 6, часть Б
     (двухэтапный пайплайн проекция->патология) — ТОТ ЖЕ 3-классовый
     таргет, что и Статья 1. Вернуться к этому датасету при работе над
     Статьёй 6.

  в) BraTS2020 (NIfTI, Kaggle-зеркало awsaf49/brats20-dataset-training-
     validation) — ВЫБРАН для Статьи 4. У каждого пациента один объём
     (240, 240, 155), срезы по оси Z — буквально реальная физическая
     последовательность одного МРТ-исследования, не суррогат.
     Расплата: другие классы, не glioma/meningioma/pituitary — только
     глиома (HGG/LGG вместе), задача сегментации, а не 3-классовая
     классификация. План Статьи 4 это ЯВНО допускает (важен метод
     сглаживания, не сохранение исходных 3 классов).

2. ВЫБРАННАЯ ЗАДАЧА КЛАССИФИКАЦИИ НА BraTS
--------------------------------------------------------------------------------
Бинарная: "срез содержит опухоль" (has_tumor, из маски _seg.nii, доля
ненулевых пикселей > 0) vs "не содержит". Обоснование: опухоль занимает
непрерывный поддиапазон Z-срезов у каждого пациента — соседние срезы
физически и содержательно похожи именно в смысле, нужном для проверки
H1/H2 плана (сглаживание помогает при содержательном порядке, не помогает
при перемешанном).

4. КОНВЕРТЕР — ГОТОВ И ПРОТЕСТИРОВАН
--------------------------------------------------------------------------------
Файл: experiments/prepare_brats_dataset.py

Что делает (на пациента):
  1. nibabel.load() модальность-объём (по умолчанию FLAIR) + _seg.nii.
  2. Отбрасывает почти пустые Z-срезы (доля ненулевых пикселей < 2%,
     MIN_BRAIN_FRACTION) — верхние/нижние срезы вне мозга.
  3. Нормализация интенсивности в uint8 (клиппинг по 1-99 перцентилям
     ненулевых вокселей, затем масштаб в [0,255]).
  4. ImagePreprocessor.process() — ТОТ ЖЕ resize->подавление фона->
     центрирование, что и для datasets/*_centered/ (переиспользование
     библиотеки, не дублирование кода).
  5. Сохраняет PNG с именем {patient_id}_slice{idx:03d}.png — порядок
     срезов сохранён в имени файла (критично для статьи 4).
  6. Пишет datasets/brats_flair_slices/metadata.csv — patient_id, slice_idx,
     path, has_tumor, tumor_pixel_fraction, brain_pixel_fraction.

Конфигурация (константы в начале файла):
  BRATS_ROOT       — путь к распакованной MICCAI_BraTS2020_TrainingData
                      (переменная окружения BRATS_ROOT, либо правка константы).
  MODALITY_SUFFIX  — "flair" по умолчанию (лучший контраст опухоли);
                      альтернативы: t1/t1ce/t2.
  MAX_PATIENTS     — 40 по умолчанию (BraTS2020 train = 369 пациентов,
                      полный набор избыточен для методологической
                      демонстрации — поправить при необходимости).
  MIN_BRAIN_FRACTION — 0.02.
  TARGET_SIZE      — (256, 256), как и остальной пайплайн.

Зависимость: nibabel>=5.0.0 — добавлена в requirements.txt и
pyproject.toml (extras "experiments").

ПРОВЕРКА (пройдена): сквозной прогон на синтетическом NIfTI-объёме
(10 срезов, искусственно внедрённая "опухоль" на срезах 4-6, пустые
крайние срезы 0 и 9) — результат корректен: 8/10 срезов сохранено (крайние
отброшены), has_tumor=True ровно на срезах 4,5,6, имена файлов сохраняют
порядок, итоговые PNG 256x256 uint8 с реальным содержимым (не пустые/не
битые).

5. СЛЕДУЮЩИЕ ШАГИ (после получения пути к скачанным данным)
--------------------------------------------------------------------------------
  1. Запустить конвертер: BRATS_ROOT="<путь>" python experiments/prepare_brats_dataset.py
  2. Написать experiments/experiment_sequential_smoothing.py (план статьи 4,
     пункт 5): 3 конфигурации на честном сплите —
       1. содержательный порядок (по patient_id + slice_idx) + smooth_adjacent_vectors
       2. тот же порядок без сглаживания (baseline)
       3. случайно перемешанный порядок + сглаживание (контроль, H2)
     Метрики: accuracy, per-class recall, сравнение всех 3.
  3. Проверить гипотезы H1 (1 > 2) и H2 (3 <= 2) из плана статьи 4.
