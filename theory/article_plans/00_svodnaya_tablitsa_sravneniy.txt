================================================================================
СВОДНАЯ СХЕМА: КАКИЕ МОДЕЛИ СРАВНИВАЮТСЯ НА КАКИХ ДАТАСЕТАХ
(портфель из 8 статей как единая исследовательская программа)
================================================================================

ИДЕЯ. Каждая статья N вводит СВОЮ технику (модель Mn) и СВОЙ датасет (Dn).
Начиная со статьи 2 датасет Dn дополнительно используется как ПЛОЩАДКА для
переобучения и честной оценки техник ИЗ ПРЕДЫДУЩИХ статей (M1..M(n-1)) — это
проверяет, переносится ли эффект техники за пределы датасета, на котором она
была впервые предложена, а не переизобретает всё заново на каждом шаге.

ДВА ТИПА ТЕХНИК (это ключевое разграничение, определяющее, где схема
работает буквально, а где — нет):

  (А) ПЕРЕНОСИМЫЕ УЛУЧШЕНИЯ КЛАССИФИКАТОРА — модификация самого
      SubspaceConjugacyClassifier / протокола сравнения, не привязанная к
      конкретной модальности данных. Принимает любую (M, N)-матрицу
      признаков — переносится на новый датасет практически без адаптации.
      Сюда относятся: M1 (критерий ранней остановки), M2 (ансамблевая
      интеграция), M6 (эвристика n_subclasses — как КОМПОНЕНТ настройки
      любой другой модели, не как отдельная модель классификации), M7
      (калибровка R(x,Y)), M8 (рекурсивный сплиттер + CNN-эмбеддинги).

  (Б) ДОМЕННО-СПЕЦИФИЧНЫЕ ТЕХНИКИ — осмысленны только при определённой
      структуре входных данных. Сюда относятся: M3 (горизонтальная/
      вертикальная развёртка — нужна честная 2D-структура сигнала), M4
      (векторизация аудио/видео — сама техника ЕСТЬ доменная адаптация,
      сравнивать её "на чужом" датасете значит тестировать не её, а нечто
      другое), M5 (иерархическая проекция→патология — нужна разметка по
      проекциям/видам, которой нет почти нигде, кроме BraTS).

--------------------------------------------------------------------------------
МАТРИЦА: СТАТЬЯ (СВОЙ ДАТАСЕТ Dn) × МОДЕЛИ ИЗ ПРЕДЫДУЩИХ СТАТЕЙ
--------------------------------------------------------------------------------

  Статья 1  (D1 = Fashion-MNIST + синтетика)
    M1 — базовая точка отсчёта цепочки, сравнивать не с чем (первая статья).

  Статья 2  (D2 = HAM10000/ISIC2018)
    + M1 — ДА, без адаптации (тип (А), тот же формат "изображение → вектор").

  Статья 3  (D3 = MRI проекта)
    + M1 — ДА, без адаптации.
    + M2 — ДА (CNN/ML-компоненты ансамбля уже обучались на этом же MRI в
      draft-method эксперименте проекта — минимум лишней работы).

  Статья 4  (D4 = ICBHI аудио + Kvasir-Capsule видео)
    + M1 — ДА, без адаптации (критерий остановки не завязан на модальность).
    + M2 — ДА, но дороже: нужны доменные CNN/ML-бейзлайны (1D-CNN для
      аудио и т.п.) вместо готовых 2D-CNN проекта.
    + M3 — ЧАСТИЧНО: для аудио-спектрограммы (время x частота) горизонталь/
      вертикаль имеют прямой физический смысл — переносится честно; для
      видео нужно доопределение (что считать "горизонтальной" развёрткой
      3D-объёма кадров) — не один-в-один перенос, а адаптация метода.

  Статья 5  (D5 = BraTS)
    + M1 — ДА, без адаптации.
    + M2 — ДА, без адаптации.
    + M3 — ДА, без адаптации (BraTS — такие же 2D-срезы, как MRI проекта).
    + M4 — НЕТ: BraTS не аудио/видео контент, категориальная
      несовместимость с техникой M4 (векторизация иной модальности не
      имеет смысла тестировать на статичных срезах).

  Статья 6  (D6 = мета-выборка MRI+MNIST+EMNIST+Fashion-MNIST)
    Особый случай: M6 — не альтернативная модель классификации, а
    КОМПОНЕНТ подбора n_subclasses для ЛЮБОЙ модели, у которой есть этот
    гиперпараметр (M1, M2, M3, M5, M7, M8). Сравнение здесь имеет форму
    "та же модель с n_subclasses от полного перебора" против "та же
    модель с n_subclasses от эвристики M6" — а не "M6 против M1..M5"
    напрямую.

  Статья 7  (D7 = MRI проекта + PatchCamelyon)
    + M1 — ДА, без адаптации, на обеих частях D7.
    + M2 — ДА, без адаптации (PatchCamelyon — тот же тип задачи,
      классификация патологии по текстуре снимка).
    + M3 — ДА, без адаптации, на обеих частях D7.

  Статья 8  (D8 = MRI проекта, тот же корпус, что D3/D7-основной)
    + M1 — ДА, без адаптации.
    + M2 — ДА, без адаптации.
    + M3 — ДА, без адаптации.
    + M7 — ДА, без адаптации (статья 8 явно строится поверх находки статьи 7).
    + M4 — НЕТ (иная модальность, категориальная несовместимость).
    + M5 — НЕТ на D8 в исходном виде: в datasets/{class}_centered/ нет
      метки проекции (в отличие от BraTS/D5) — честное сравнение с M5
      потребовало бы либо привлечь D5 вместо D8, либо разметить проекции
      в D8 вручную, что выходит за рамки статьи 8.

--------------------------------------------------------------------------------
ЧТО ЭТО ДАЁТ ДИССЕРТАЦИИ
--------------------------------------------------------------------------------
К статье 8 накапливается таблица вида "техника x датасет x accuracy/время",
пригодная для отдельной, синтезирующей главы диссертации (не статья, а
глава сравнения): какие из 8 техник переносятся между доменами устойчиво
(кандидаты — M1, M2, M7 — работают на ВСЕХ датасетах без исключения), какие
дают эффект только в родном домене (M3, M5), и какие являются доменными
адаптациями, а не универсальными улучшениями (M4).

--------------------------------------------------------------------------------
ОГОВОРКА О СТОИМОСТИ
--------------------------------------------------------------------------------
Не все клетки матрицы одинаково дёшевы: honest tuned-протокол на MRI
(N=65536) уже занимал от нескольких минут до ~25 минут на один прогон
поиска гиперпараметров (artifacts/full_library_search_mri_report.json).
Полное заполнение матрицы для всех N=8 статей — это, по сути, отдельный
инженерный проект (десятки честных прогонов); реалистичный план для одной
статьи — не более 2-3 моделей из предыдущих статей на её датасете, а не
весь накопленный список.
