ПЛАН ПЕРЕНОСА ПРОЕКТА НА БОЛЕЕ МОЩНОЕ ЖЕЛЕЗО (mission_6states)
================================================================================
Текущая машина: NVIDIA GeForce GTX 1650, 4096 МБ VRAM, driver 560.76,
CUDA 12.6. Python 3.11.9, torch 2.14.0+cu126, torchvision 0.29.1+cu126.
Эта конфигурация — потолок для части рычагов из
article4_remaining_accuracy_levers.txt (п.8-10 там прямо требуют больше
памяти/времени). План ниже — что перенести, как настроить среду заново,
и что конкретно станет возможным на более мощной машине.

================================================================================
ЧАСТЬ 1 — ЧТО ПЕРЕНОСИТЬ (размеры замерены 2026-10-09)
================================================================================

1. КОД (обязательно, маленький) — весь `C:\mission_6states`, кроме
   каталогов ниже, которые перечислены отдельно. Проще всего — через git,
   если репозиторий уже инициализирован (`git status` в корне), либо
   прямое копирование папки (пара МБ без данных/.venv).

2. `data/BraTS2020/` — 39.86 ГБ, сырые NIfTI-объёмы. СОДЕРЖИТ ВСЕ 369
   пациентов официального BraTS2020 Training Set (проверено — мы
   обработали только 160 из них, но сырые данные на диске уже полные).
   Варианты:
     а) Скопировать папку напрямую (внешний диск/локальная сеть) — быстрее,
        если канал позволяет передать ~40 ГБ.
     б) Заново скачать на новой машине вручную через браузер
        (https://www.kaggle.com/datasets/awsaf49/brats20-dataset-training-validation,
        см. `article4_notes.txt` — именно так датасет попал в проект в
        первый раз, у Claude Code нет доступа к Kaggle API пользователя).
   Рекомендация: если есть внешний диск/быстрая сеть — вариант (а)
   быстрее и гарантированно даёт тот же набор данных (не нужно проверять
   совпадение версии датасета).

3. `datasets/brats_flair_slices/` — 0.90 ГБ, уже обработанные PNG-срезы
   (FLAIR+T1+T1ce+T2+маски для 160 пациентов). Можно скопировать как
   есть (небольшой, экономит время предобработки) ИЛИ пересобрать с нуля
   на новой машине из сырых данных (`prepare_brats_dataset.py` ->
   `prepare_brats_segmentation_masks.py` -> `prepare_brats_multimodal_slices.py`),
   если план — расширять на все 369 пациентов (см. Часть 3, п.2) — тогда
   пересборка всё равно потребуется, можно сразу делать это на новой
   машине и не копировать промежуточный результат для 160.

4. `artifacts/` — 0.83 ГБ, отчёты/графики/JSON. Переносить ПО ЖЕЛАНИЮ
   (для продолжения сравнения "было/стало" с текущими честными
   результатами) — не критично для возобновления экспериментов, но
   полезно для истории.

5. `.venv/` — 1.11 ГБ — НЕ переносить, это venv текущей (неиспользуемой)
   виртуальной среды — рабочий Python на этой машине на самом деле
   системный (`C:\Users\<user>\AppData\Local\Programs\Python\Python311`),
   не `.venv`. На новой машине всё равно переустанавливать окружение
   заново (ниже) из-за другой GPU/CUDA-версии — переносить виртуальное
   окружение бессмысленно в любом случае.

6. Память Claude Code (`C:\Users\<user>\.claude\projects\...\memory\`) —
   НЕ часть проекта, но стоит знать: если новая машина — новый профиль
   пользователя/новая установка Claude Code, вся история решений проекта
   (честность методологии, найденные баги, принятые решения) окажется
   недоступна новой сессии. Если планируется продолжать работу с Claude
   Code на новой машине — взять с собой файлы памяти (или попросить новую
   сессию прочитать `medical_article_requirements.txt`/txt-файлы в корне
   проекта, которые и так переедут вместе с кодом).

================================================================================
ЧАСТЬ 2 — НАСТРОЙКА СРЕДЫ НА НОВОЙ МАШИНЕ
================================================================================

1. Python 3.11+ (текущая версия 3.11.9, сборки `torch`/`torchvision`
   ниже собраны под cp311 — для другой версии Python нужны другие wheel).

2. Библиотека проекта:
       pip install -e ".[dev,experiments,reports]"
   (есть nibabel, opencv, matplotlib, python-docx и т.д. — полный список
   см. `pyproject.toml`).

3. PyTorch С CUDA — САМЫЙ ВАЖНЫЙ ШАГ, версия ЗАВИСИТ ОТ GPU новой
   машины:
   а) Выяснить версию драйвера/CUDA новой карты:
          nvidia-smi
      (строка "CUDA Version: XX.X" в выводе — это МАКСИМАЛЬНАЯ CUDA,
      которую поддерживает драйвер, не обязательно та, что нужно ставить
      — PyTorch-сборки обратно совместимы в пределах мажорной версии).
   б) Проверить доступные сборки на индексе PyTorch (пример для cu126,
      подставить нужный под новую карту — cu121/cu124/cu128 и т.д.):
          pip index versions torch --index-url https://download.pytorch.org/whl/cu126
   в) Установить ТОЧНО СОВПАДАЮЩИЕ версии torch/torchvision из ОДНОГО
      индекса (несовпадение версий torch/torchvision — частый источник
      рантайм-ошибок):
          pip install --index-url https://download.pytorch.org/whl/cuXXX torch==X.Y.Z+cuXXX torchvision==X.Y.Z+cuXXX
   г) На этой машине установка 2.6 ГБ wheel с первой попытки падала по
      хэшу (нестабильная сеть, не повреждение пакета) — если повторится,
      просто повторить команду 2-3 раза, НЕ менять версию в панике.
   д) Проверить:
          python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"

4. Переменные окружения для подготовки данных (при пересборке с нуля):
       BRATS_ROOT=<путь>\MICCAI_BraTS2020_TrainingData
   (см. docstring `prepare_brats_dataset.py`).

================================================================================
ЧАСТЬ 3 — ЧТО СТАНЕТ ВОЗМОЖНЫМ НА БОЛЕЕ МОЩНОЙ МАШИНЕ
================================================================================
(соответствует "тяжёлым" пунктам article4_remaining_accuracy_levers.txt)

1. ПОЛНОЕ РАЗРЕШЕНИЕ (240x240, нативное BraTS) вместо 128x128/96x96 —
   сейчас ограничено 4 ГБ VRAM. Прямой, задокументированный в литературе
   вклад в Dice.

2. ВСЕ 369 ПАЦИЕНТОВ вместо 160 — сырые данные уже на диске (см. Часть 1,
   п.2), нужно только поднять `MAX_PATIENTS` в `prepare_brats_dataset.py`
   и перегенерировать датасет (FLAIR+маски+T1/T1ce/T2 для всех).

3. ИСТИННАЯ 3D-ОБРАБОТКА (3D U-Net по патчам или целым объёмам 155x240x240,
   4 модальности) — САМЫЙ весомый рычаг по литературе (топ BraTS-решения,
   Dice 0.88-0.90+ — используют 3D), но и самый требовательный к VRAM.
   Нереалистично на 4 ГБ, становится практичным на 12+ ГБ (типичные
   конфигурации для этого — 3D-патчи 64-128 вокселей, batch 1-4).

4. ПОЛНЫЙ АНСАМБЛЬ (5+ моделей, не 2-3) + больший бюджет эпох на
   каждую — быстрее по времени при больших VRAM/вычислительной мощности
   карты, можно не экономить на MAX_EPOCHS/patience.

5. БОЛЬШИЙ BATCH_SIZE — при том же числе эпох даёт более стабильные
   градиенты (сейчас BATCH_SIZE=4 из-за памяти, в т.ч. из-за системного
   OOM, не только GPU) — на новой машине можно поднять до 16-32.

6. СКОМБИНИРОВАТЬ K-СОСЕДНИЕ СРЕЗЫ + ВСЕ 4 МОДАЛЬНОСТИ ОДНОВРЕМЕННО
   (до 20 входных каналов при K=5) — на GTX 1650 рискованно по памяти,
   комфортно на более мощной карте.

7. MIXED PRECISION (`torch.cuda.amp`) даст дополнительный множитель
   эффективности поверх перечисленного — стоит включить сразу при
   переезде, не дожидаясь отдельного запроса.

================================================================================
РЕКОМЕНДУЕМЫЙ ПОРЯДОК ПОСЛЕ ПЕРЕЕЗДА
================================================================================
1. Настроить среду (Часть 2), проверить `torch.cuda.is_available()`.
2. Скопировать/пересобрать данные (Часть 1, п.2-3) — решить СРАЗУ,
   расширяем ли на 369 пациентов (если да — пересборка данных всё равно
   нужна, лучше сделать её один раз с полным датасетом).
3. Повторить `experiment_article4_accuracy_boost.py` как регрессионную
   проверку (тот же честный сплит seed=42) — убедиться, что перенос
   среды не сломал воспроизводимость (ожидаемое число — Dice ~0.78,
   см. project_article4_accuracy_boost.md в памяти).
4. Применять тяжёлые рычаги из этой Части 3 по очереди, с промежуточными
   честными замерами (не подбирать конфигурацию по тестовому числу —
   см. предупреждение медицинского рецензента про p-hacking, п.5
   medical_article_requirements.txt).
