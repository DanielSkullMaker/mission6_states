================================================================================
0. КОНТЕКСТ ПРОЕКТА
================================================================================

Проект реализует метод Fursov (подпространственная сопряжённость) для
классификации МРТ-изображений опухолей мозга.

Классы данных:
  - glioma      (глиома)
  - meningioma  (менингиома)
  - pituitary   (гипофиз)
  - test        (тестовая выборка: 75 изображений, по 25 на класс)

Размер изображений после препроцессинга: 256×256 px.
Размерность вектора признаков: 65536 (256×256, горизонтальный или вертикальный обход).

Количество подклассов (кластеров) на каждый класс опухоли: 8 (n_subclasses=8,
подбирается экспериментально, в ноутбуках зафиксировано 8).
Итого глобальных подклассов при классификации: 24 (8 × 3 класса).
Базис каждого подкласса для классификации: ровно 2 опорных вектора (subclass_factor=2).

================================================================================
1. THEORY ALIGNMENT — КАНОНИЧЕСКИЙ АЛГОРИТМ КЛАСТЕРИЗАЦИИ
================================================================================

Источник: описание алгоритма кластеризации (теория проекта).
Область применения: эталонные (обучающие) изображения одного класса патологии
(одно множество векторов X shape (M, N) на класс).

----------------------------------------------------------------------
1.1. МАТЕМАТИЧЕСКИЕ ОПРЕДЕЛЕНИЯ
----------------------------------------------------------------------

Косинусный критерий (сходство) для векторов a, b:
  cos(a, b) = (a·b) / (||a|| · ||b||)

Показатель сопряжённости вектора x с подпространством, натянутым на столбцы Y
(N×k):
  R(x, Y) = (xᵀ Y (Yᵀ Y)⁻¹ Yᵀ x) / (xᵀ x)

Реализация в библиотеке:
  - cos(a, b)           → cosine_similarity_matrix() или pairwise из неё
  - R(x, Y)             → conjugate_criterion(x, Y) в core/metrics.py
  - (Yᵀ Y)⁻¹            → compute_gram_inverse(Y) с reg_param (Тихонов)

Диапазон R: [0, 1] (clip в metrics.py).

----------------------------------------------------------------------
1.2. ФАЗА A — ПОИСК ЦЕНТРОВ КЛАСТЕРОВ (n_subclasses центров)
----------------------------------------------------------------------

Выполняется на множестве эталонных векторов одного класса.

ШАГ A.1 — Первая пара центров (2 центра):
  Перебрать ВСЕ возможные пары векторов (i, j), i ≠ j.
  Для каждой пары вычислить cos(v_i, v_j).
  Сохранить пару с МИНИМАЛЬНым значением cos — наиболее «непохожие» изображения.
  Результат: center_indices = [idx1, idx2].

  ⚠ Не путать с NB4: там для КАЖДОГО i ищется argmin_j cos(i,j) → trio_list[M×3].
  Канон — одна глобальная пара.

ШАГ A.2 — Третий центр:
  Y = matrix(center_1, center_2) размерности N×2.
  Для каждого оставшегося x: вычислить R(x, Y).
  Выбрать x с МИНИМАЛЬНым R → третий центр.

ШАГ A.3 — Четвёртый и последующие центры (до n_subclasses):
  Y = matrix(все найденные центры) размерности N×k, k = текущее число центров.
  Для каждого оставшегося x: R(x, Y).
  Выбрать x с МИНИМАЛЬНым R → следующий центр.
  Повторять, пока len(centers) < n_subclasses.

Инвариант: при поиске k-го центра Y строится из (k-1) уже найденных центров
(растущая матрица), а не из фиксированной пары.

----------------------------------------------------------------------
1.3. ФАЗА B — ФОРМИРОВАНИЕ КЛАСТЕРОВ ВОКРУГ ЦЕНТРОВ
----------------------------------------------------------------------

После фазы A: n_subclasses центров (по 1 вектору на кластер).
remaining = все векторы класса \ центры.

ШАГ B.1 — Cosine seed (второй вектор в каждый подкласс):
  Для КАЖДОГО центра c отдельно:
    из remaining выбрать вектор v с МИНИМАЛЬНым cos(v, center_c)
    (наиболее «непохожий» на центр по косинусу — второй элемент пары).
  Результат: n_subclasses пар (center_c, v_c), в каждом подклассе ровно 2 вектора.
  Использованные v удалить из remaining.

  Примечание: в каждом подклассе формируется подпространство Y_s (N×2).

ШАГ B.2 — Conjugacy growth (наполнение кластеров):
  Условие входа: в каждом подклассе уже ≥ 2 вектора (после B.1 выполнено).
  Пока remaining не пуст:
    1. Для каждого x ∈ remaining и каждого подкласса s:
         вычислить R(x, Y_s), где Y_s — текущая базисная матрица (N×k_s).
         На этапе классификации k_s=2; при росте k_s может увеличиваться,
         но для финального базиса классификатора фиксируем k=2 (см. NB6–8).
    2. Найти пару (x*, s*) с МАКСИМАЛЬНым R(x*, Y_{s*}).
    3. Присоединить x* к подклассу s*, обновить Y_{s*}.
    4. Удалить x* из remaining.

  Критично: присоединять СТРОГО ПО ОДНОМУ вектору за итерацию (глобальный argmax
  по всем remaining × всем подклассам). Нельзя bulk-assign множество в один кластер.

----------------------------------------------------------------------
1.4. ФАЗА C — КЛАССИФИКАЦИЯ (применение к тестовым векторам)
----------------------------------------------------------------------

Для каждого класса патологии: n_subclasses базисов Y_{c,s} (N×2).
Глобально: C × n_subclasses подпространств (напр. 3×8=24).

Для тестового x:
  R_{c,s} = R(x, Y_{c,s})
  subclass* = argmax_{c,s} R_{c,s}
  class* = c(subclass*)  [0..7→class0, 8..15→class1, ...]

Опционально (NB8): proportion = R_max / mean(R_others) - 1.

----------------------------------------------------------------------
1.5. МАППИНГ: ТЕОРИЯ → МОДУЛИ БИБЛИОТЕКИ → ФАЗЫ РЕФАКТОРИНГА → НОУТБУКИ
----------------------------------------------------------------------

| Шаг теории              | Модуль (канон)                    | Фаза | Ноутбук      | Legacy / parity      |
|-------------------------|-----------------------------------|------|--------------|----------------------|
| A.1 Глобальная min-cos  | global_pair.py                    | 3.1  | —            | NB4 (trio_list) ⚠    |
| A.2–A.3 Центры min R    | reference_centers.py              | 3.2  | NB5          | —                    |
| B.1 Cosine 2-й вектор   | subclass_seed.py                  | 3.3  | NB6 ~        | —                    |
| B.2 Max R, по 1 вектору | subclass_growth.py                | 3.4  | NB7          | —                    |
| Фасад A+B               | clusterer.py (SubspaceClusterer)  | 3.5  | —            | текущий clusterer ⚠  |
| Экспорт базисов k=2     | subclass_export.py                | 3.6  | NB6–7 CSV    | —                    |
| Классификация           | classifier.py                     | 4    | NB8          | —                    |
| Preprocessing           | preprocessing/*                   | 1    | NB1–2        | —                    |
| Векторизация            | features/*                        | 2    | NB3          | —                    |

Условные обозначения:
  ✅ — прямое соответствие
  ~  — частичное / эвристически близко
  ⚠  — расхождение с каноном; сохранять как legacy для parity

----------------------------------------------------------------------
1.6. СООТВЕТСТВИЕ SubspaceClusterer (текущий код) ТЕОРИИ
----------------------------------------------------------------------

  _select_initial_centers():
    A.1 глобальный argmin cos по всем парам     → ✅ совпадает с теорией
    A.2–A.3 argmin R, Y растёт с центрами       → ✅ совпадает с теорией

  fit_predict() — наполнение кластеров:
    Сразу max R, growing basis                   → ⚠ нет фазы B.1 (cosine seed)
    Один вектор за итерацию (global argmax)      → ✅ совпадает с B.2
    Базис растёт > 2                             → ⚠ для классификации нужен k=2

  Действие при рефакторинге: переписать SubspaceClusterer как фасад
  GlobalMinCosinePairFinder → ReferenceCenterBuilder → CosineSecondVectorAttacher
  → ConjugacyClusterGrowth, с опцией freeze_basis_at=2 для экспорта в classifier.

----------------------------------------------------------------------
1.7. РАСХОЖДЕНИЯ НОУТБУКОВ С КАНОНОМ (parity, не source of truth)
----------------------------------------------------------------------

  NB4: per-vector trio_list ≠ теория A.1 (глобальная пара).
       NB5 берёт initial pair из NB4 вручную (напр. индекс 8) — ещё одно расхождение.

  NB7: ratio к среднему (master) — расширение B.2, strategy="master".
  NB8: классификация по 24 базисам k=2 — ✅ совпадает с фазой C.

  Parity-тесты: pytest.mark.notebook_parity — сравнение с CSV ноутбуков.
  Theory-тесты: pytest.mark.theory — проверка канонического алгоритма на synthetic.

2. КЛЮЧЕВЫЕ РАСХОЖДЕНИЯ: ТЕОРИЯ vs НОУТБУКИ vs БИБЛИОТЕКА
================================================================================

2.1. Шаг A.1 (первая пара)
  Теория:     глобальный argmin cos по всем парам (одна пара).
  NB4:        для каждого i — argmin_j cos → trio_list[M×3].
  SubspaceClusterer: глобальный argmin → ✅ теория.
  → Канон: global_pair.py. NB4 → legacy.

2.2. Шаги A.2–A.3 (центры через min R)
  Теория = NB5 = SubspaceClusterer._select_initial_centers (после пары) → ✅

2.3. Фаза B.1 (cosine второй вектор к каждому центру)
  Теория:     явный шаг B.1.
  NB6:        ~похожая логика (farthest vector), но как отдельный pipeline stage.
  SubspaceClusterer: отсутствует → ❌
  → Новый модуль subclass_seed.py.

2.4. Фаза B.2 (max R, sequential)
  Теория = NB7 (частично) = SubspaceClusterer loop → ✅ с оговоркой на B.1.

2.5. Фиксированный базис k=2 для классификации
  Теория (фаза C): Y_s (N×2).
  NB6–8: экспорт 16 векторов = 8 пар.
  SubspaceClusterer: базис не ограничен → нужен freeze/export k=2.

2.6. Staged CSV pipeline vs единый fit()
  Ноутбуки: промежуточные CSV между этапами (удобно для экспериментов).
  Теория: единый алгоритм, stages — implementation detail.
  → FursovPipeline.run_stage() для CSV; SubspaceClusterer.fit() для канона in-memory.

2.7. Preprocessing и vectorization
  Только в NB1–3. Не часть теории кластеризации, но нужны для end-to-end pipeline.

2.8. Математическое ядро
  final_step() из ноутбуков ≡ conjugate_criterion() — ✅
  cos_criterea() из NB4 содержит баг (norm первого вектора) — не воспроизводить.

--- ФАЗА 3.2: ReferenceCenterBuilder (ТЕОРИЯ A.2–A.3, NB5) ---

ПРОМПТ:
  Реализуй algorithms/reference_centers.py.

АЛГОРИТМ (КАНОН = NB5):
  Вход: X, initial_pair=(idx1, idx2) из GlobalMinCosinePairFinder
  centers = [idx1, idx2]
  while len(centers) < n_subclasses:
      Y = X[centers].T                    # (N, k), k растёт
      remaining = indices not in centers
      R_values = conjugate_criterion(X[remaining], Y)
      new_center = remaining[argmin(R_values)]
      centers.append(new_center)
  return centers  # length n_subclasses

API:
  class ReferenceCenterBuilder:
      def __init__(self, n_subclasses=8, reg_param=1e-8): ...
      def fit(self, X, initial_pair: tuple[int,int]) -> np.ndarray: ...

КРИТЕРИИ:
  - len(centers_) == n_subclasses
  - Y при каждой итерации включает ВСЕ предыдущие центры
  - notebook_parity: compare с glioma_class_core_vectors.csv (может отличаться
    если NB5 использовал пару из NB4, а не global pair)

ИСТОЧНИК: теория A.2–A.3, NB5

--- ФАЗА 3.3: CosineSecondVectorAttacher (ТЕОРИЯ B.1, NB6 ~) ---

ПРОМПТ:
  Реализуй algorithms/subclass_seed.py — канонический шаг B.1.

АЛГОРИТМ (КАНОН):
  Вход: X, center_indices (n_subclasses,)
  remaining = all indices \ center_indices
  pairs = []
  for c in center_indices:
      sims = cosine_similarity(X[remaining], X[c])  # cos с центром
      v_idx = remaining[argmin(sims)]              # min cos = max «непохожесть»
      pairs.append((c, v_idx))
      remaining.remove(v_idx)
  return pairs  # shape (n_subclasses, 2)

API:
  class CosineSecondVectorAttacher:
      def fit(self, X, center_indices) -> np.ndarray: ...
      # pairs_ shape (S, 2)

КРИТЕРИИ:
  - Каждый центр получает ровно один второй вектор
  - Все 2×S индексов уникальны
  - notebook_parity (~): glioma_new_classes.csv может отличаться

ИСТОЧНИК: теория B.1; NB6 — reference

--- ФАЗА 3.4: ConjugacyClusterGrowth (ТЕОРИЯ B.2, NB7 ~) ---

ПРОМПТ:
  Реализуй algorithms/subclass_growth.py — канонический шаг B.2.

АЛГОРИТМ (КАНОН):
  Вход: X, initial_pairs (S×2) из CosineSecondVectorAttacher
  Y_bases[s] = X[pairs[s]].T   # (N, 2) каждый
  labels[all paired indices] = assigned
  remaining = unassigned indices
  while remaining:
      build R_matrix shape (len(remaining), S):
          R_matrix[r,s] = conjugate_criterion(X[remaining[r]], Y_bases[s])
      (r*, s*) = argmax R_matrix
      assign remaining[r*] to s*, append vector to Y_bases[s*]  # basis grows
      remove from remaining
  return labels_, Y_bases

  Опции:
    freeze_basis_at: int | None = 2
      если 2 — после fit оставить только первые 2 столбца Y_s для export/classifier
    strategy: "default" | "master"
      master (NB7): ratio R(x,s)/mean(R) при отборе представителей

API:
  class ConjugacyClusterGrowth:
      def fit(self, X, pairs) -> tuple[np.ndarray, list[np.ndarray]]: ...

КРИТЕРИИ:
  - Ровно один вектор assign за итерацию while
  - Все M векторов получают label
  - theory test: на synthetic кластерах sanity check

ИСТОЧНИК: теория B.2; NB7 — reference (strategy master)
